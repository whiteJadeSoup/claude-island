5.1 主路径 ── 主线程上 focus(view) 的完整时序

5.1.1 时序图上没画但仍需注意的两件事

  • PyObjC import 缓存：第 11 步的 _check_pyobjc_available() 只在 module 加载或 fast-path 第一次失败时真正执行 import； 后续是模块级 _HAS_PYOBJC: bool | None 三态读（None=未检测 / True=可用 / False=不可用）。
  • WindowDeactivate 是 Qt 的副作用：最后一条 Note 不依赖我们写代码 —— Qt 监听 macOS 的应用激活事件；NSRunningApplication.activate 一旦成功， 我们的进程不再 frontmost，Qt 触发 QEvent::WindowDeactivate → ExpandedWindow.event() 内现有逻辑调 self.hide()。

5.2 Worker 任务 ── _PaneSelectTask.run() 的完整决策

5.2.1 _build_focus_event 的最小实现

def _build_focus_event(handler_name: str, arg1: str, host_pid: int):
    """
    构造 aevt/psbr AppleEvent 调用一个 subroutine handler。
    用 NSAppleEventDescriptor 包装参数，避开字符串模板转义。
    """
    target = NSAppleEventDescriptor.descriptorWithProcessIdentifier_(os.getpid())
    event = NSAppleEventDescriptor.appleEventWithEventClass_eventID_targetDescriptor_returnID_transactionID_(
        FourCharCode('ascr'),
        FourCharCode('psbr'),
        target,
        kAutoGenerateReturnID,
        kAnyTransactionID,
    )
    event.setParamDescriptor_forKeyword_(
        NSAppleEventDescriptor.descriptorWithString_(handler_name),
        FourCharCode('snam'),
    )
    args = NSAppleEventDescriptor.listDescriptor()
    args.insertDescriptor_atIndex_(NSAppleEventDescriptor.descriptorWithString_(arg1), 0)
    args.insertDescriptor_atIndex_(NSAppleEventDescriptor.descriptorWithInt32_(host_pid), 0)
    event.setParamDescriptor_forKeyword_(args, FourCharCode('----'))
    return event

此实现细节是为说明"参数走 descriptor 不走字符串拼接"而展开； 具体 4-char codes 与 PyObjC 绑定细节交给实现期参照 Apple AEDataModel 文档。

5.3 跨线程边界细节

fast-path 涉及两个跨线程交接点。本节明确每个点上"谁拥有内存所有权"。

5.3.1 为什么 _PaneSelectTask 必须冻结字段

主线程构造 task 时，view.jump_target / view.session.pid 可能在数毫秒后被 snapshotter 新一帧覆盖（WorldSnapshot 是不可变值对象，但 view 实例本身不是单例）。 如果 task 持有 view 强引用，worker run 时读到的字段就可能是"过期 view"。
解决：构造时把必要原始值（host_pid / session_id / tty）复制进 frozen 字段， 不持 view 引用。
代价：每 task 几十字节内存；几乎为零。

5.3.2 worker → 主线程的回流 ── 显式没有

潜在需求v1 是否实现原因
pane select 失败 → UI 闪一下提示 否 主线程已让宿主前置，用户感知"焦点已经到了"；闪提示反而干扰
cache invalidate → 状态栏指示 否 事件极稀有，靠 log；不值得拉一条 Signal 通道
backlog reject → 提示用户 否 同上 + 出现意味着 iTerm 已僵死，UI toast 也无济于事

"worker 不持 QObject" 的不变量让我们规避所有"跨线程 Signal-from-non-QThread"陷阱 （项目历史上踩过 reactivex QtScheduler 与 Qt 主线程的兼容性坑，见 tests/integration/test_reactivex_qt_compat.py）。

5.4 关键边缘流的具体路径

5.4.1 PyObjC ImportError 路径（图 7 替代分支）

focus(view):
  if _HAS_PYOBJC is None:           # 首次调用
      try:
          from AppKit import NSRunningApplication
          _HAS_PYOBJC = True
      except ImportError:
          _HAS_PYOBJC = False
          log.info("iterm2 fast-path disabled; PyObjC unavailable")

  if not _HAS_PYOBJC:
      return self._legacy_focus(view)   # 现有 subprocess osascript 路径

  return self._fast_path_focus(view)

5.4.2 host_pid 解析失败路径

def _resolve_host_pid(view) -> int | None:
    jt = view.jump_target
    if jt and jt.terminal_pid > 0:
        return jt.terminal_pid
    if view.session.pid > 0:
        return _iterm_host_pid(view.session.pid)
    return None

# 在 fast-path 入口：
host_pid = _resolve_host_pid(view)
if host_pid is None:
    return self._legacy_focus(view)

5.4.3 NSRunningApplication.activate 返回 NO

极罕见。不试第二次 —— 重试在主线程上会再吃一次 latency 预算且失败概率不会下降。 直接降级到 legacy path 是最快/最不破坏 G1 的选择。
