iTerm Focus Performance — Detail Design

§8 · Migration & Compatibility

Traces to Overview · G4（PyObjC 不可用降级）· G5（其他 dispatch 不变） + §1 契约演化的可观察影响

一句话总结

本变更无数据迁移、无配置变更、无 API 破坏。 落地方式 = 单次合并；回滚方式 = git revert。 真正需要讨论的"兼容性"集中在运行时降级（PyObjC 缺失）与契约语义演化 （focus() 返回 True 的含义微调）。

8.1 没有 schema migration ── 为什么

常见 migration 触发点本变更
数据库 schema 改动无任何数据库
持久化 JSON / TOML 文件格式无文件读写
环境变量 / 配置项新增不新增（明确决定，§3.3 reject 阈值硬编码）
命令行参数不变
IPC 协议（hook ↔ daemon）不变；fast-path 只读已有 jump_target
包依赖pyobjc-framework-Cocoa 已声明在 pyproject.toml:31；不需新增

8.2 落地步骤（部署视角）

对照 design-plan-guide 给的模板"add column → dual-write → backfill → switch readers → drop old"： 本变更每一步都不需要。原因是 fast-path 是"前置叠加层"， 失败时退到与改动前完全一致的代码路径 —— 不存在"老数据要迁过来 / 新读者要切过去"的状态。

8.3 回滚路径

回滚触发条件动作恢复时间
生产观察 G1 / G2 不达标 git revert + 重新发版 分钟级
个别用户机器 fast-path 异常 无需 revert：fast-path 自动 fallback 到现有路径（§4 设计） 瞬时
NSAppleScript 在某 macOS 版本上整体不可用 同上 —— cache invalidate 阈值触发后该机器 worker 走 subprocess 兜底 3 次点击后自动降级
FocusWorker 线程在某机器上死锁累计崩溃 引入 module-level CLAUDE_ISLAND_DISABLE_ITERM_FAST_FOCUS=1 环境变量（v2 才加）
v1 应对方案 = 用户 revert 到上一版		 v2 加：瞬时；v1：等待新版本

为什么 v1 不加 kill-switch 环境变量

项目 CLAUDE.md 设计原则反对"未触发的需求驱动的 feature flag"。 fast-path 的失败是per-call 自动降级到现有 fallback，不需要全局开关。 如果出现"整个 fast-path 在某机器上必须禁用"的需求且 fallback 机制不足以应对，再补 kill-switch 也来得及。

8.4 契约演化的影响面（详）

§1 已说明 focus() 返回 True 的含义演化。本节做完整影响面盘点。

消费者读返回值读后做什么语义改动后是否仍正确
TerminalDispatcher.dispatch 是 仅 log.info("dispatch: ... returned False") 仍正确 ── 语义"宿主前置"比"pane 精度落地"是更弱保证，但 dispatch 不区分
ExpandedWindow._on_row_clicked 否 不读返回值；靠 WindowDeactivate 自动隐藏面板 仍正确
CapsuleWindow 否 不调 FOCUS 不涉及
测试 stub StubDispatcher.dispatch 在 test_dispatcher.py 是 用于断言"是否触发" 仍正确（True 仍代表"路径走通"）
任何未来想根据 "pane 精度真落地" 决策的消费者 不存在 — 未来若需要，应在 worker 侧暴露独立 Signal，不改 focus() 同步返回值

8.5 运行时降级矩阵

枚举"用户机器上哪些条件不满足 → fast-path 哪一段会被降级"，便于运维诊断。

条件检测点降级范围用户感知
PyObjC 完全缺失 模块首次 import 整个 fast-path 退回 ~250 ms 同步行为
PyObjC 部分（AppKit 有，Foundation 缺） NSAppleScript 模块 import 时 worker pane select；fast-path 主线程仍工作 宿主前置 fast，pane 精度退回 subprocess
System Events 权限被吊销 worker 收到 errno=-1743 fast-path worker；fallback 也将失败 点击无响应；log.error 引导用户去设置
iTerm Automation 权限被吊销 同上但 errno 在 tell application "iTerm" 块内 同上 同上
jump_target 缺失（旧 hook.py / 非 hook 进 session） fast-path 入口 多 ~0.3 ms 的 _iterm_host_pid 调用 无感（仍在 G1 预算内）
iTerm 进程僵死 worker backlog > 10 reject 新提交（§3.3） 面板隐藏正常，pane 精度停在旧位置
iTerm 未运行 NSRunningApplication 返回 nil fast-path 转 fallback fallback 也会失败（iTerm 不存在）；点击无响应 = 与现状一致

8.6 与其他终端适配器的关系

适配器是否受本变更影响说明
ITerm2Adapter 是 本设计的主体
TerminalApp（macOS Terminal.app） 否 独立 focus() 实现；用 Terminal.app 自己的 AppleScript 字典；不在本次范围（Non-Goal）
GenericMacAdapter 否 调 focus_host_app，与 iTerm 不重叠
WindowsTerminalAdapter / GenericWindowsAdapter 否 Windows-only；模块级 import guard 已确保 macOS 代码不会被 import 到 Windows 进程
