1.1 Component diagram（C4 L3 · iTerm2 Focus 子系统内部）

本节范围限定在 ITerm2Adapter.focus() 调用链。 外部边界（TerminalDispatcher.dispatch、focus_host_app fallback、_iterm_host_pid 祖先链查找）已在 Overview Architecture 中固化，不在本节复述其内部。

NEW 新增组件 · MOD 契约改动 · UNCHANGED 仅作为 fallback · 外部 API

关键决策两处：左侧 NSRunningApplication.activate 走主线程、~0.3 ms，立刻触发面板 WindowDeactivate 自动隐藏；右侧 worker 线程上的 cached NSAppleScript 承担 pane 精度（40–200 ms），fire-and-forget。

1.2 组件契约（按调用顺序展开）

ITerm2Adapter.focus(view, *, siblings=()) → bool MOD

参数
view: SessionView — 必含 session.pid > 0 或者 view.jump_target 至少有一个识别字段（iterm_session_id / terminal_pid）；否则进入 focus_host_app 兜底。
siblings — 接受但忽略，与 WT 适配器保持 kwargs 一致。
返回
True：主线程 fast-path 成功完成"将 iTerm2 宿主进程置前"， pane select 已提交到 worker（不保证完成）。
False：主线程 fast-path 失败（PyObjC ImportError / 无 host_pid / NSRunningApplication.activate 返回 NO），并且 fallback 链路也已尝试且失败。
前置条件
在 Qt 主线程上调用。 view.adapter_id == "iterm2"（由 dispatcher 保证）。
错误
不抛异常 —— 所有失败转 False 或转 fallback 路径。 内部任何异常被适配器外层 try/except 兜住并 log.warning。
契约演化（与现状对比）
旧：True = pane 精度成功（osascript 返回 ok）。
新：True = 宿主应用已前置（用户已经看到 iTerm2），pane 精度异步落地。
调用方语义不变：dispatcher 只用 bool 决定是否记 warning， UI 不依赖 pane 精度的同步反馈（已确认：_on_row_clicked 点完就靠 WindowDeactivate 自动隐藏面板，不读 bool）。

FocusFastPath NEW

主线程编排器。状态无关、线程亲和（必须主线程）。

activate_host_app(host_pid: int) → bool
调用 NSRunningApplication.runningApplicationWithProcessIdentifier_(host_pid) 取得目标 app，再调 activateWithOptions_(NSApplicationActivateIgnoringOtherApps)。 返回 PyObjC 调用是否完成（None app → False；activate 返回 NO → False）。
耗时：warm ~0.3 ms（in-process AppKit，不出进程）。
错误：ImportError 上抛（由 focus() 捕获）；其他异常吞掉返回 False。
schedule_pane_select(view: SessionView, host_pid: int) → None
构造一个 _PaneSelectTask（QRunnable 子类）， 交给 FocusWorker.submit()。fire-and-forget，立即返回。
线程：调用方必须在主线程；任务体执行在 worker 线程。
幂等性：多次提交同 view 是安全的（pane select 两次 = 同一结果）。

AppleScriptCache NEW

模块级单例。生命周期 = 进程；首次访问时懒编译。 保存两份 NSAppleScript 实例对应 id-match / tty-match 两个 subroutine 模板。

get_id_handler() → NSAppleScript
返回已编译的 id-match 脚本实例。脚本体声明 on focusByID(sessionID, hostPID) handler。
线程安全：内部用 threading.Lock 保护"懒编译 + 首次返回"。 一旦编译完成，executeAppleEvent_error_ 在单一 worker 上串行调用 （由 FocusWorker maxThreadCount=1 保证）。
get_tty_handler() → NSAppleScript
同上，对应 on focusByTTY(targetTTY, hostPID)。
invalidate() → None
丢弃当前缓存（下次访问重新编译）。 用途：连续 N 次执行返回 errOSAScriptError 时由 worker 触发， 防止"脚本对象本身坏了"的极端情况长期卡死。 门限在 §3 状态机定义。
错误
懒编译失败抛 RuntimeError("AppleScript compile failed: ...") — 意味着脚本模板本身有语法错（开发期问题，不应进生产）。 worker 捕获并降级到 osascript subprocess 兜底。

FocusWorker NEW

QThreadPool 实例，setMaxThreadCount(1)，FIFO。 进程单例（模块级），通过 focus_worker() 函数取得。

submit(task: QRunnable) → None
入队即返。任务体调用 AppleScriptCache.get_*_handler() + NSAppleScript.executeAppleEvent_error_(event)。
线程模型
maxThreadCount=1 的核心理由：Apple 文档明确 NSAppleScript "not thread-safe" —— 但允许 "serialised on a single thread"。 单线程池天然提供这个不变量，无需额外锁。
队列饱和
人类点击速率上限 ~10 Hz，单次 pane select ~100 ms，理论稳态队长 ≤ 1。 v1 不设上界。监控指标：worker 长期 backlog > 3 时记 WARNING（在 §4 错误处理细化）。
关停
进程退出时 QThreadPool.waitForDone(timeout=500ms)；超时后任务被丢弃 — pane select 没完成不会阻止退出。

_PaneSelectTask(QRunnable) NEW

worker thread 上承载一次 pane 选择尝试，内含 fallback 链。

__init__(*, host_pid, session_id, tty)
构造时三个字段冻结。session_id / tty 至少有一项非空（调用方保证）。
run() → None
  1. 有 session_id → 调用 id_handler。ok 即返回。
  2. 否则 / id miss → 有 tty 则调用 tty_handler。ok 即返回。
  3. 仍 miss → 不重试，记 log.info("iterm2 pane select miss: ...")。 Main-thread 已经把宿主置前，用户至少看到 iTerm。
  4. NSAppleScript 抛错 → 记 log.warning + 累计 AppleScriptCache 失败计数；达阈值后 cache.invalidate()，让下一次重新编译。
不变量
无返回值；不持有 view 强引用之外的状态。 多个 _PaneSelectTask 在 worker 串行执行（FocusWorker 保证）。

focus_host_app(pid: int) → bool UNCHANGED

现有兜底（_macos_common.py:177）。 当 fast-path 任何一个前置条件失败（PyObjC ImportError、无 host_pid）时， focus() 直接调用它 —— 保持当前 ~250 ms 同步行为，但只用于退化路径。 契约不变，仅扩大调用比例下降的范围。

_iterm_host_pid(claude_pid: int) → int | None UNCHANGED

现有祖先链查找（iterm2.py:562）。仅在 view.jump_target.terminal_pid 缺失时调用。0.3 ms 量级，可继续在主线程执行。

1.3 对外契约的最小变更面

调用方是否需要改动原因
TerminalDispatcher.dispatch 否 仍是 bool method(view, **kwargs) 调用；签名一致。
ExpandedWindow._on_row_clicked 否 当前实现不读 bool 返回值（依赖 WindowDeactivate 自动隐藏面板）。
__main__.py 装配 否 FocusWorker / AppleScriptCache 都是模块级懒初始化，不需要外部注入。
tests/platform_/test_iterm2_adapter.py 是 新增 PyObjC 路径 + worker 提交断言；现有 subprocess osascript 断言变为 fallback 场景。
