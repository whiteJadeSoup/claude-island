本节范围一句话

本变更无任何持久化 schema。新增的全部状态都在进程内存，生命周期 ≤ 进程。 本节定义这些内存结构的字段、不变量与访问模式； 状态机转移与阈值放在 §3，外部错误观察放在 §4。

2.1 进程内状态全景

关键边界：SessionView / WorldSnapshot 不新增任何字段。 fast-path 所需的全部数据都来自 已存在的 view.jump_target 与 view.session.pid。 这保证 distinct_until_changed(render_key) 的结构性等价语义不被打破， 也避免给 snapshot 管线引入新的脏路径。

2.2 _PaneSelectTask ── 冻结字段表

字段 类型 / 默认 约束 来源
host_pid int 必须 > 0。构造时校验，否则 ValueError（视为编程错误）。 view.jump_target.terminal_pid 或运行时 _iterm_host_pid() 解析结果。
session_id str | None 非空时必须是 hook 捕获的 iTerm session id；不做格式校验（iTerm 内部用 UUID-ish 字符串）。 view.jump_target.iterm_session_id，hook 未捕获或 jump_target 为空时为 None。
tty str | None 非空时必须以 /dev/ 开头（psutil 在 macOS 上的返回格式）；不做更细校验。 主线程构造 task 前调用 psutil.Process(pid).terminal()；失败则 None。
created_at float · time.monotonic() 仅供 worker 计算端到端 wall-time 用，不参与决策。 构造瞬间。
跨字段不变量：session_id is not None or tty is not None。 两者皆空意味着主线程上没有任何线索可走 AppleScript，应当直接走 focus_host_app 兜底，不构造 task。 构造函数 assert 该不变量。

实现形态

@dataclass(frozen=True, slots=True)
class _PaneSelectTask(QRunnable):
    host_pid: int
    session_id: str | None
    tty: str | None
    created_at: float = field(default_factory=time.monotonic)

    def __post_init__(self) -> None:
        if self.host_pid <= 0:
            raise ValueError("host_pid must be positive")
        if not self.session_id and not self.tty:
            raise ValueError("session_id or tty required")
        # QRunnable.__init__ via super() is required for Qt's C++ bookkeeping;
        # work around frozen=True by routing through object.__setattr__.
        QRunnable.__init__(self)

frozen + slots 是为了与项目里现有 SessionView/Session 的不可变值对象语义保持一致（见 CLAUDE.md 设计原则 #7）。 冻结避免 worker 运行时被主线程意外修改字段。

2.3 AppleScriptCache ── 内部态

属性类型初值读写规则
_id_script NSAppleScript | None None 懒初始化。读：get_id_handler() 触发，需持 _lock 检查后赋值。 写：仅在懒编译 / invalidate() 时。
_tty_script NSAppleScript | None None 同上，独立编译。
_lock threading.Lock fresh lock 仅保护"懒编译 + 字段写"的临界段。 脚本对象的 executeAppleEvent_error_ 调用不持锁 —— 由 FocusWorker maxThreadCount=1 提供执行串行化。
_consecutive_failures int 0 worker 在 note_failure() 中递增； get_*_handler 成功返回 ok 时由 worker 调 note_success()（隐式定义为重置）归零。阈值 / 触发 invalidate 的规则在 §3。

线程亲和性 ── 显式说明

操作哪个线程并发上限
首次 get_*_handler()（含懒编译）worker1（_lock 序列化）
已编译后的 get_*_handler()worker1（pool maxThreadCount=1）
NSAppleScript.executeAppleEvent_error_worker1（同上）
invalidate()worker（由 task run() 触发）1
note_failure() / note_success()worker1

为什么不暴露 main-thread 的 invalidate()

有想过让用户在"权限设置改完"后从托盘菜单按钮调 invalidate()。否决理由： 跨线程访问 NSAppleScript 实例语义未定义；让缓存只在 worker 线程被改， 是最便宜的不变量。如果未来需要 UI 触发清缓存，应当通过给 worker 投递一个 _InvalidateTask 间接达成，而不是 main thread 直接调。

2.4 AppleScript 模板 ── 从字符串拼接到 subroutine

现有 _FOCUS_SCRIPT_BY_ID_TEMPLATE / _FOCUS_SCRIPT_TEMPLATE 是把 host_pid / session_id / tty 直接 str.format 进脚本体的"模板字符串"。 fast-path 路径下脚本只编译一次，所以参数不能再嵌进源码 —— 改成 AppleScript 的 subroutine，参数通过 NSAppleEventDescriptor 传入。

项id 模板tty 模板
handler 签名 on focusByID(sessionID, hostPID) on focusByTTY(targetTTY, hostPID)
返回 "ok"（找到并 select 成功） / "miss"（遍历结束未匹配）
输入字符类型 两个参数都是 AppleScript text（UTF-8 / 自动转 unicode text）；hostPID 在 AppleScript 内 as integer。
转义需求 无。参数通过事件描述符传入，AppleScript 引擎不再做字符串内联， 所以现有 _escape_applescript_string() 不再用于这条路径 （仍保留供 fallback subprocess 路径继续用）。

模板代码（写在脚本字面量里，编译一次）

_FOCUS_BY_ID_SOURCE = """
on focusByID(sessionID, hostPID)
    tell application "System Events"
        set frontmost of (first process whose unix id is (hostPID as integer)) to true
    end tell
    tell application "iTerm"
        repeat with w in windows
            repeat with t in tabs of w
                repeat with s in sessions of t
                    if (id of s as text) is sessionID then
                        select s
                        select t
                        select w
                        return "ok"
                    end if
                end repeat
            end repeat
        end repeat
        return "miss"
    end tell
end focusByID
"""

tty 模板结构同形，仅判定条件从 id of s 换成 tty of s。 两份脚本独立编译为独立 NSAppleScript 实例 —— 不合并成一个多 handler 脚本， 是为了：(a) 任一边出问题（语法 / 权限）可以独立 invalidate； (b) 单脚本里两个 handler 共享一个 _lock 没收益但增加耦合。

2.5 FocusWorker ── 队列与生命周期

属性 / 行为说明
_pool: QThreadPool 独立实例（非 QThreadPool.globalInstance()）。 隔离避免我们的 task 被 Qt 内部其他 QRunnable 排队卡住。
setMaxThreadCount(1) 核心不变量，参 §2.3 的线程亲和。
队列容量 无显式上限。稳态队长 = 人类点击间隔 ÷ task 平均耗时 ≈ 1。 观察：backlog() > 3 时 WARNING；> 10 时启动溢出丢弃策略（在 §3 状态机里）。
停机 shutdown(timeout_ms=500) → pool.waitForDone(timeout_ms)。 到时未完成的 task 被丢弃；不阻塞进程退出。

2.6 持久化 schema —— N/A

本变更不引入 SQLite 表 / JSON 配置文件 / 文件系统写。 唯一外部副作用是 NSRunningApplication.activate 与 NSAppleScript 调用本身， 属于"对 OS 状态的瞬时操作"，不留持久痕迹。

因此 design-plan-guide 模板里要求的"migration path with rollback"在本节退化为单点： 回滚 = git revert。无需数据库 backfill、双写、版本号字段等。 完整兼容性讨论（含 PyObjC ImportError 降级、运行期 feature 切换）放 §8。
